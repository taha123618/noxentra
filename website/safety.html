Security & Trust Architecture

Noxentra is engineered so operators stay in control of every binary, every network target, and every AI-assisted step.

1. List-form subprocesses only

All tool execution uses explicit argument arrays through a unified runner with SIGTERM → SIGKILL escalation on timeout or cancel. shell=True and curl | bash install patterns are prohibited.

2. Zero auto-execution & plan validation

AI-generated plans (/goal) are validated in code to reject sudo/doas, shell -c wrappers, and shell metacharacters, and still pause for explicit [y]/[e]/[s]/[q] confirmation.

3. Grounded AI & <scan_data> isolation

Recommendations map strictly to the 64-tag taxonomy in tags.py. Untrusted tool output passed to --ai-summary is isolated inside <scan_data> delimiters.

4. Local-first secrets (0600)

Optional LLM and GitHub API tokens are written exclusively to ~/.noxentra/.env with mode 0600, never committed or printed back to logs.

5. Scope exclusions (--scope-out)

Both initial targets and discovered hosts matching --scope-out globs or exclusion files are filtered and logged before any step runs. engagement.json and findings.json are written atomically.

6. Suggest-only /find discovery

/find ranks vetted catalog tools first, then GitHub repositories with zero model calls. Bookmarked repos save to ~/.noxentra/found.yaml without executable commands.
